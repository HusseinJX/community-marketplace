# Demo mode (full)

## Demo Mode
In demo, gated vendor pages resolve a representative demo member via `lib/demo-server.ts` `demoMemberId()` (by the demo-type cookie) so the admin UIs render with sample data instead of the "link your profile" gate. Demo **writes still no-op** (`resolveActor` has no demo path). **`NEXT_PUBLIC_DEMO_MODE=1`** opens the vendor portal *without Clerk auth* so each member type's admin UI is testable/refinable quickly. `lib/demo-admin.ts` (`isDemoMode()`, `DEMO_TYPES`, `writeDemoCookies`) + `components/DemoTypeSwitcher.tsx`. The gate is **`app/vendor/layout.tsx`** (`!userId && isDemoActive()` → skip the `/vendor/sign-in` redirect), *not* middleware — `middleware.ts` is only `clerkMiddleware` + an `x-pathname` header. `/demo` is an admin type picker (Vendor/Artist/Community + category). **The admin demo is NOT public in prod** — `isDemoActive()` requires (when `NEXT_PUBLIC_DEMO_MODE!=1`) the demo-password unlock cookie (`JOINDEMO_COOKIE`) on top of the type cookie, and the `/demo` launcher prompts for `JOINDEMO_PASSWORD` (shared with `/joindemo`; set on CapRover). A self-set `demo_admin_type` cookie alone no longer opens the portal. Demo collab fixtures live in **`lib/demo-collab.ts` only** — the API serves them and `NetworkManager` imports the same ones, so home and Messages can't disagree (they used to have separate id-spaces, which silently broke `?collab=` deep links).

- **⚠️ THE BUILD TRAP — read before any prod build.** `NEXT_PUBLIC_*` is **inlined at build time**, and `.env.local` (demo `=1` for local work) is loaded by `next build`. So a build from a dev machine bakes **demo mode ON** into prod → `/vendor/*` serves the whole portal (products, orders, customer DMs) **to anyone, unauthenticated**. `.env.production.local` now pins `NEXT_PUBLIC_DEMO_MODE=0` (it outranks `.env.local` in Next's env order), which is the only thing keeping prod builds safe — **never remove that line**. Same trap applies to `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`: local is `pk_test` (dev instance), and `.env.production.local` pins `pk_live`.
- **Always verify before uploading a build:** `PORT=3100 npx next start` → `curl -sI localhost:3100/vendor` must be **307 → /vendor/sign-in**. A **200 means demo mode is ON** and the build must not ship. (Grepping the bundle doesn't work — minification folds the inlined constant away.)
- Prod is **OFF** and verified on every deploy (2026-07-16). Only turn on in a throwaway preview env.
